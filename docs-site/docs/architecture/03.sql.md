# SQL Layer

In Agora, SQL is treated as a first-class internal API.

Repositories do not build queries dynamically.
They call database functions that encapsulate all data access logic.

---

## Why SQL Functions

Using SQL functions provides:
- Reduced attack surface
- Stronger guarantees on returned data shape
- Easier auditing
- Centralized logic

From Go, we prefer:

SELECT agora.get_feed_posts(user_id);

Over:
- Ad-hoc queries
- String concatenation
- ORM-generated SQL

---

## Rules

- One function per use case
- Explicit parameters
- No hidden behavior
- Predictable return types

Functions should not:
- Encode business rules
- Perform authorization checks
- Contain application logic

---

## JSON Usage

JSON is used intentionally:
- To aggregate complex structures (e.g. stances)
- To reduce query complexity on the Go side

The expected JSON shape must always be documented and stable.

---

## Migrations

During early development, schemas are rebuilt via development scripts.

Formal migrations will be introduced at v1 once the data model stabilizes.
