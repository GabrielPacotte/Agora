# Domain Layer

The domain layer is the most important part of Agora.

Everything else exists to serve it.

---

## Purpose

The domain defines:
- What exists in the system
- What is valid
- What is forbidden

It encodes business rules as invariants that cannot be bypassed.

---

## Design Principles

- Domain objects are validated at creation
- Invalid states are unrepresentable
- Mutability is tightly controlled
- Collections are returned as copies
- Errors are explicit and meaningful

The domain is allowed to reject data aggressively.

---

## What the Domain Does Not Know

The domain has no knowledge of:
- HTTP
- JSON
- SQL
- Authentication mechanisms
- Tokens or sessions
- Pagination or filtering concerns

These are all delivery or infrastructure concerns.

---

## Errors

Domain errors represent **business violations**, not technical failures.

Examples:
- Invalid credentials
- Forbidden actions
- Invalid content
- Broken invariants

They are intentionally reusable across layers.

---

## Why This Matters

A strong domain allows:
- Confident refactoring
- Predictable behavior
- Reduced need for defensive programming elsewhere

If the domain is correct, everything built on top of it becomes simpler.
